# 배포 설명 — IntelliJ → GitHub Actions(CI/CD) → 아마존 라이트세일 (수업용)

배포는 서버실의 신입 AI 직원 **테포**가 맡습니다. 사장님이 대화방에서 "서버에 올려 줘"라고 하면 다음 순서로 진행됩니다.

## 1. 전체 그림

```
개발자(IntelliJ) ─ commit/push ─▶ GitHub (비공개 저장소)
                                    │
                                    ├─ CI  (.github/workflows/ci.yml)      PR·가지마다: MySQL 8 서비스 + ./gradlew test bootJar
                                    └─ CD  (.github/workflows/deploy.yml)  main 마다: CI → bootJar → scp → 서버에서 교체 → HTTPS 확인
                                                                              │
사장님(브라우저) ─ HTTPS + 로그인 ─▶ 라이트세일 인스턴스 (Ubuntu 24.04, 서울)
                                    ├ Caddy           443 → 127.0.0.1:8080, Let's Encrypt 인증서 자동 (주소: IP를-줄표로.sslip.io)
                                    ├ systemd         publisher-dashboard.service (java -jar app.jar --spring.profiles.active=prod)
                                    └ /etc/publisher/dashboard.env (권한 600: DB 접속 정보·사장님 비밀번호)
                                          │ 같은 지역 사설망
                                          ▼
                                   라이트세일 관리형 MySQL 8 (외부 공개 안 함)
```

## 2. 테포의 스크립트 (`~/my-publisher/tepo/`)

| 스크립트 | 하는 일 | 돈 |
|---|---|---|
| `preflight.sh` | 도구(aws·gh) 설치, AWS·GitHub 열쇠 확인, 테스트, 요금제·가격 조회 → `ops/plan.env` | 안 듦 |
| `create-infra.sh` | SSH 열쇠 → 인스턴스 → 고정 IP·방화벽(22·80·443) → MySQL → `ops/infra.env` | **듦** |
| `server-setup.sh` | 로그인 계정 생성 → bootJar → 서버에 Java·Caddy·systemd 설치 → HTTPS 확인 | — |
| `github-setup.sh` | 저장소·workflow·.gitignore → commit → 비공개 저장소 → Secrets 4개 → push → Actions 지켜보기 | — |
| `deploy-status.sh` · `health.sh` | 최근 Actions 결과·실패 로그, 서버 상태 | — |

**안전장치**
- `create-infra.sh`는 사장님 승인 기록 `ops/approved.txt`가 **마지막 준비 확인(`ops/plan.env`)보다 새것일 때만** 실행됩니다. 이 파일은 쭌이 [배포 제안] 승인을 받은 뒤 씁니다.
- 이미 있는 자원은 다시 만들지 않습니다. 여러 번 실행해도 요금이 두 번 나오지 않습니다.
- 지우기 명령(`delete-instance`, `delete-relational-database`, `release-static-ip`, `gh repo delete`)은 `.claude/settings.json`에서 막혀 있습니다. 삭제는 사람이 콘솔에서 합니다.
- 테포는 위 스크립트만 실행할 수 있습니다. aws·gh·git·ssh를 직접 칠 권한이 없습니다.
- 비밀값은 `ops/secrets/`(권한 600), 서버 환경 파일(600), GitHub Secrets에만 둡니다. git에도 채팅에도 남기지 않습니다.

## 3. GitHub Secrets

| 이름 | 값 |
|---|---|
| `LIGHTSAIL_HOST` | 고정 IP |
| `LIGHTSAIL_USER` | `ubuntu` |
| `LIGHTSAIL_SSH_KEY` | 서버 SSH 개인키 (`ops/secrets/lightsail_key`) |
| `LIGHTSAIL_DOMAIN` | `IP를-줄표로.sslip.io` |

## 4. 서버 설정 (`application-prod.yml`)

- **DB**: `PUBLISHER_DB_URL / USER / PASSWORD` (MySQL, `sslMode=REQUIRED`)
- **표 만들기**: Flyway가 `db/migration/V1__init.sql`로 만들고, JPA는 `ddl-auto: validate`로 엔티티와 맞는지만 확인합니다.
  - 엔티티를 바꾸면 `V2__설명.sql`을 **새로** 만듭니다. V1은 고치지 않습니다.
- **로그인**: Spring Security 폼 로그인입니다. 사장님 계정은 `BOSS_USERNAME / BOSS_PASSWORD`이고, 8자 미만이면 앱이 시작되지 않습니다.
  - 화면 폼과 fetch POST 모두 CSRF 토큰을 확인합니다. 로그인하지 않은 API 요청은 401을 받습니다.
- `/actuator/health`만 로그인 없이 열립니다. 배포 확인용입니다.
- 앱은 `127.0.0.1:8080`에서만 받고, 바깥 요청은 Caddy(HTTPS)를 거칩니다.

## 5. 되돌리기

`/opt/publisher/deploy-on-server.sh`가 새 jar로 바꾼 뒤 2분 안에 `/actuator/health`가 UP이 되지 않으면 `app.jar.prev`로 되돌리고 실패로 끝냅니다. Actions에도 빨간불이 켜집니다.

## 6. 수업에서 돈 없이 보여 주기

```bash
bash ~/my-publisher/tepo/mock/run-practice.sh
```
가짜 aws·gh·ssh로 전체 순서를 실행하고, 불린 명령을 순서대로 보여 줍니다. 승인 없이 멈추는지, 두 번 실행해도 다시 만들지 않는지도 확인합니다.

## 7. 확인한 것과 못 한 것

- **확인함**
  - 진짜 MySQL 8에서 Flyway V1 적용과 `validate` 통과, 한글·이모지 저장 (`MySqlMigrationTest`)
  - prod 모드의 로그인·CSRF·401·health (`SecurityEnabledTest`, 브라우저 시험)
  - actionlint 검사 통과
  - 가짜 AWS·GitHub로 전체 순서 실행
  - 실제 쭌 팀에서 테포가 준비 확인을 하고, 열쇠가 없을 때 멈추는 것
- **못 함**: 실제 AWS 계정으로 라이트세일 만들기, 실제 GitHub Actions 실행
