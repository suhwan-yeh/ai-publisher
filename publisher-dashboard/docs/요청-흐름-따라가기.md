# 요청 흐름 따라가기 (처음 배우는 사람용)

이 문서는 브라우저에서 무슨 일이 생겼을 때 서버 안에서 코드가 어떤 순서로 실행되는지 따라갑니다.
문서의 예시 값은 모두 관리 화면을 실제로 실행해서 얻은 값입니다(요청·응답 원문, 실행된 SQL).
낯선 낱말은 [용어 풀이](용어-풀이.md)에서 찾아보세요.

## 읽는 법

코드 곳곳에 **흐름 번호표**가 붙어 있습니다. 모양은 `[흐름 B-③]`입니다.

1. IntelliJ에서 **Ctrl + Shift + F**(전체 검색)를 누릅니다.
2. `흐름 B-`를 검색합니다.
3. 번호 순서(①→②→③…)대로 파일을 열어 읽습니다.

모든 파일 맨 위에는 같은 순서의 설명 일곱 가지가 있습니다.

| 항목 | 내용 |
|---|---|
| `[1] 역할` | 이 파일이 하는 일 |
| `[2] 받는 것 → 내보내는 것` | 실제로 실행해서 얻은 입력과 출력 |
| `[3] 앞뒤 파일` | 이 파일을 부르는 곳과 이 파일이 부르는 곳 |
| `[4] 메서드 목록` | 메서드(또는 필드·구역)마다 하는 일과 흐름 번호 |
| `[5] 먼저 알 용어` | 읽기 전에 알아야 할 낱말 |
| `[6] 읽는 순서` | 파일 안에서 어디부터 읽을지 |
| `[7] 다 읽고 확인` | 스스로 답해 볼 질문 두 개 |

줄마다 붙은 주석은 다섯 가지 방법으로 씁니다.

| 방법 | 예 |
|---|---|
| 실제 값 | `// 예) text="  좋아요 " → t="좋아요"` |
| 긴 줄 나누기 | `// (1) … (2) … (3) …` 실행 순서대로 |
| 없으면 | `// 없으면: 빈 글이 서비스까지 간다` |
| 실제 원문 | HTTP 요청·응답, 실행된 SQL을 그대로 |
| 용어 형식 | `뜻 / 받는 것 / 결과` 세 줄 |

## 흐름 목록

| 흐름 | 한 줄 설명 | 시작하는 곳 | 검색할 글 |
|---|---|---|---|
| **A** | 주소를 치면 화면(HTML)이 온다 | 브라우저 주소창, 링크 | `흐름 A-` |
| **B** | 버튼을 누르면(이벤트) fetch가 JSON을 주고받는다 | `chatpanel.js` | `흐름 B-` |
| **B′** | 3초마다 새 메시지를 가져온다(폴링) | `chatpanel.js` | `흐름 B′-` |
| **C** | 폼을 보내면 처리한 뒤 다른 화면으로 이동한다(PRG) | `index.html`의 주문 폼 | `흐름 C-` |
| **D** | 잘못되면 상태코드와 오류 문장이 온다 | `ApiExceptionHandler` | `흐름 D-` |
| **E** | 사무실 화면이 2초마다 바뀐다 | `office.js` | `흐름 E-` |
| **F** | 서버가 혼자 기록 파일을 읽어 DB를 채운다 | `ScanScheduler` | `흐름 F-` |

## 먼저 알아 둘 그림: 계층

```
브라우저 ──요청──▶ Controller ──▶ Service ──▶ Repository ──▶ DB
        ◀─응답──                     │
                                     └──▶ Client ──▶ fakechat(쭌), tmux
```

- **Controller**: 요청을 받고 응답 모양을 정합니다. 계산이나 저장은 Service에 맡깁니다.
- **Service**: 무엇을 어떤 순서로 할지 정합니다(업무 규칙).
- **Repository**: DB에 넣고 꺼냅니다.
- **Client**: 이 프로그램 밖의 프로그램과 통신합니다.
- 화살표는 한 방향입니다. Controller가 Repository를 바로 부르지 않습니다.

Controller는 두 종류입니다.

| | `@Controller` (controller 패키지) | `@RestController` (api 패키지) |
|---|---|---|
| 돌려주는 것 | 템플릿 이름 → **HTML** | 객체 → **JSON** |
| 누가 부르나 | 주소창, 링크, 폼 | 자바스크립트의 `fetch` |
| 예 | `GET /chat` → `chat.html` | `POST /api/chat` → `{"id":103,…}` |

## 흐름 A — 주소를 치면 화면이 온다 (요청 → Controller → 템플릿 → HTML)

주소창에 `http://localhost:8080/`을 치고 Enter를 누른 순간부터 화면이 보일 때까지입니다.

```
 브라우저                         서버 (Spring)
┌───────────────────┐  GET /
│ ① 주소창 · 링크    │ ─────────────▶ ② DashboardController.index(Model model)
└───────────────────┘                     │  @GetMapping("/")
                                          ▼
                                      DashboardService.allBooks()
                                          │  select … from book b1_0 order by b1_0.created_at
                                          ▼
                                      model.addAttribute("books", …)
                                          │
                                          ▼
                                      ③ return "index"
                                          │  templates/index.html 을 찾는다
                                          ▼
                                      ④ 타임리프가 ${books} 자리를 채운다
┌───────────────────┐  200 text/html     │  th:each="v : ${books}" → 책 카드 5개
│ ⑤ 화면에 그린다    │ ◀──────────────────┘
└───────────────────┘
```

| 번호 | 파일 · 위치 | 일어나는 일 | 배우는 것 |
|---|---|---|---|
| A-① | `templates/fragments.html` · header 조각의 `<nav>` 링크 | 링크를 누르면 브라우저가 GET 요청을 보낸다 | `<a href>`, GET |
| A-② | `controller/DashboardController.java` · `index()` (`/books/{id}`, `/team`, `/chat`, `/office`도 같은 모양) | 주소에 맞는 메서드가 실행된다 | `@Controller`, `@GetMapping`, `@PathVariable`, `Model` |
| A-③ | `DashboardController.index()`의 `return "index"`, `service/DashboardService.java` | 서비스가 DB에서 값을 모으고, 컨트롤러가 템플릿 이름을 돌려준다 | 생성자 주입, 템플릿 이름 |
| A-④ | `templates/index.html`, `fragments.html` | `${…}` 자리에 값을 넣어 HTML을 완성한다 | `th:text`, `th:each`, `th:if`, `th:href="@{…}"`, `th:replace` |

**실제 응답 (줄임)**

```
HTTP/1.1 200
Content-Type: text/html;charset=UTF-8

<!doctype html>
<html lang="ko">
…
  <a href="/books/3"><b style="font-size:18px">꼬리 살랑, 첫 산책</b></a>
  <div class="muted"><span>실용서</span> · <span>3장, 2934자</span> · <span>6시간 전</span> 업데이트</div>
```

템플릿의 `th:text="${v.book().displayTitle()}"`가 `꼬리 살랑, 첫 산책`이 되었습니다. 브라우저가 받은 HTML에는 `th:` 속성이 남아 있지 않습니다.

### 직접 해 보기
1. `/`를 열고 **F12 → Network** 탭에서 첫 줄(문서)을 누릅니다. Response에 완성된 HTML이 있습니다.
2. 브라우저에서 **페이지 소스 보기**(Ctrl+U)를 엽니다. `th:` 속성과 `<!--/*` 주석이 보이지 않는 것을 확인합니다.
3. 중단점: `DashboardController.index()`의 첫 줄. `model`에 무엇이 들어가는지 봅니다.
4. 없는 책 `/books/999`를 열면 404가 됩니다(흐름 D-③).

### 스스로 답해 보기
- `return "index"`를 `return "home"`으로 바꾸면 무엇이 보일까요? (`templates/home.html`이 없어 500)
- 타임리프는 서버와 브라우저 중 어디에서 실행될까요?

## 흐름 B — "보내기"를 누르면 (이벤트 → fetch → REST API → JSON)

대화방에서 글을 쓰고 **보내기**를 누른 순간부터 말풍선이 생길 때까지입니다.

```
 브라우저                                서버 (Spring)
┌──────────────────────────┐
│ ① chatpanel.js           │  POST /api/chat
│   submit 이벤트 → send() │  {"text":"좋아요, 이대로 진행해 주세요."}
│   fetch(...)             │ ───────────────────▶ ② ChatApiController.send()
└──────────────────────────┘                          @RequestBody : JSON → SendMessageRequest
                                                      @Valid       : 빈 글이면 여기서 끝 (→ 흐름 D-①)
                                                            │
                                                            ▼
                                                      ③ ChatService.send()
                                                          FakechatClient.send() → POST 127.0.0.1:8787/upload
                                                            │
                                                            ▼
                                                      ④ ChatMessageRepository.save()
                                                          insert into chat_message ...
                                                            │
                                                            ▼
                                                      ⑤ ChatMessageResponse.from(엔티티)
                                                          엔티티 → 응답 DTO
                                                            │
┌──────────────────────────┐  201 Created              ▼
│ ⑦ chatpanel.js           │  {"id":103,"fromBoss":true,…}
│   render() 로 말풍선 추가│ ◀─────────────────── ⑥ ResponseEntity.created(...).body(dto)
└──────────────────────────┘
```

| 번호 | 파일 · 위치 | 일어나는 일 | 배우는 것 |
|---|---|---|---|
| B-① | `static/js/chatpanel.js` · `addEventListener('submit')`, `send()` | 보내기 이벤트를 받아 `fetch`로 POST | 이벤트 리스너, `preventDefault`, `fetch`, `JSON.stringify` |
| B-② | `api/ChatApiController.java` · `send()`, `dto/SendMessageRequest.java` | JSON을 객체로 바꾸고 규칙을 검사 | `@RestController`, `@PostMapping`, `@RequestBody`, `@Valid`, record |
| B-③ | `service/ChatService.java` · `send()`, `client/FakechatClient.java` · `send()` | 쭌에게 전달 | `@Service`, `@Transactional`, multipart HTTP |
| B-④ | `repository/ChatMessageRepository.java` · `save()` | DB에 INSERT | `JpaRepository` |
| B-⑤ | `dto/ChatMessageResponse.java` · `from()` | 엔티티를 응답 모양으로 바꿈 | 엔티티를 그대로 내보내지 않는 이유 |
| B-⑥ | `api/ChatApiController.java` · `send()`의 return | 201과 JSON으로 응답 | `ResponseEntity`, 상태코드 201, Location |
| B-⑦ | `static/js/chatpanel.js` · `send()`의 `.then`, `render()` | 응답을 받아 말풍선을 그림 | `.then`, 상태코드 확인, DOM 만들기 |

**실제 요청과 응답**

```
POST /api/chat HTTP/1.1
Content-Type: application/json

{"text":"좋아요, 이대로 진행해 주세요."}
```
```
HTTP/1.1 201
Location: /api/chat/103
Content-Type: application/json

{"id":103,"fromBoss":true,"text":"좋아요, 이대로 진행해 주세요.","at":"2026-11-09T21:46:33.776008Z","channel":"web","files":[]}
```

**실행된 SQL (B-④)**

```
insert into chat_message (at,attachment_paths,attachments,channel,direction,team_name,text,unique_key,id) values (?,?,?,?,?,?,?,?,default)
```

### 직접 해 보기
1. `/chat`을 열고 **F12 → Network** 탭을 엽니다. 메시지를 보냅니다.
2. 목록에서 `chat`(Method: POST)을 누릅니다.
   - **Headers**: Status Code `201`, `Location: /api/chat/…`
   - **Payload**: `{"text":"…"}` — B-①이 보낸 것
   - **Response**: `{"id":…,"fromBoss":true,…}` — B-⑥이 돌려준 것
3. 중단점: `ChatApiController.send()`의 첫 줄. "관리화면 실행"을 벌레 모양(디버그) 버튼으로 켜고 보내면 그 줄에서 멈춥니다. **F7**(안으로 들어가기)로 `ChatService.send()` → `save()`까지 따라갑니다.
4. 브라우저 없이 보내기 (우분투 창):
```bash
curl -i -X POST http://localhost:8080/api/chat -H 'Content-Type: application/json' -d '{"text":"안녕하세요"}'
```

### 스스로 답해 보기
- B-②에서 `@Valid`를 지우면 빈 글은 어디에서 막힐까요? (힌트: `ChatService.send()`의 첫 부분)
- B-④가 실패하면 쭌에게는 이미 전달됐을까요? `@Transactional`은 무엇을 되돌리고 무엇을 못 되돌릴까요?
- B-⑤를 건너뛰고 엔티티를 그대로 돌려주면 JSON에 무엇이 더 보일까요? (`uniqueKey`, `direction` 등)

## 흐름 B′ — 3초마다 새 메시지 (폴링)

쭌의 답장은 쭌이 대화 기록 파일에 남깁니다. 서버가 그 파일을 읽어 DB에 넣어도 브라우저는 알 수 없으므로, 브라우저가 3초마다 물어봅니다.

```
 chatpanel.js                       서버
 ① poll()  ── GET /api/chat?after=102 ──▶ ② ChatApiController.poll(after)
                                              ▼
                                          ③ ChatService.messagesAfter(102)
                                              │  기록 파일의 새 줄을 먼저 읽고(흐름 F-④)
                                              │  id 가 102 보다 큰 메시지를 찾는다
                                              ▼
                                          ④ new ChatPollResponse(online, messages)
 ⑤ .then → render(m) ◀── 200 JSON ──────── return
    setTimeout(poll, 3000) → 다시 ①
```

**실제 응답**

```
HTTP/1.1 200
{"online":true,"messages":[{"id":103,"fromBoss":true,"text":"좋아요, 이대로 진행해 주세요.","at":"2026-11-09T21:46:33.776008Z","channel":"web","files":[]}]}
```

- 새 메시지가 없으면 `"messages":[]`가 옵니다.
- 내가 보낸 103번은 B-⑦에서 이미 그렸습니다. 그래서 폴링으로 다시 와도 `render()`의 첫 줄이 같은 `data-id`를 찾아 그리지 않습니다.

### 직접 해 보기
- Network 탭에서 3초마다 `chat?after=…`가 생기는 것을 봅니다. `after=` 숫자가 화면의 마지막 말풍선 `data-id`와 같은지 확인합니다.
```bash
curl -s "http://localhost:8080/api/chat?after=0"
```

### 스스로 답해 보기
- `setInterval(poll, 3000)` 대신 `.finally`에서 `setTimeout`을 다시 거는 이유는? (응답이 늦을 때 요청이 겹쳐 쌓이지 않게)

## 흐름 C — 폼을 보내면 처리한 뒤 다른 화면으로 (PRG: Post → Redirect → Get)

첫 화면의 **새 책 주문하기** 폼은 자바스크립트 없이 브라우저가 직접 보냅니다.

```
 index.html 폼  ── ① POST /order (text=…) ──▶ ② ChatPageController.order(@RequestParam text)
                                                 ▼
                                             ③ ChatService.order(text)
                                                 │  쭌에게 전달 + book_order, chat_message 저장
                                                 ▼
                                             ④ return "redirect:/chat"
 브라우저 ◀── 302  Location: /chat ─────────────┘
    └── GET /chat ──▶ ChatPageController.chat() → chat.html  (흐름 A)
```

**실제 요청과 응답**

```
POST /order HTTP/1.1
Content-Type: application/x-www-form-urlencoded

text=%EA%B3%A0%EC%96%91%EC%9D%B4…        ← "고양이 나오는 짧은 동화 써 줘"
```
```
HTTP/1.1 302
Location: http://localhost:8080/chat
Content-Length: 0
```

**실행된 SQL (C-③)**

```
insert into book_order (at,chat_key,text,id) values (?,?,?,default)
insert into chat_message (at,attachment_paths,attachments,channel,direction,team_name,text,unique_key,id) values (?,?,?,?,?,?,?,?,default)
```

실패하면(쭌이 출근 전, 빈 글) `redirect:/`로 첫 화면에 돌아갑니다. 안내 문장(`error`)과 적었던 글(`draft`)은 **flash**로 한 번만 전달됩니다.

| 번호 | 파일 · 위치 | 배우는 것 |
|---|---|---|
| C-① | `templates/index.html` · `<form method="post" th:action="@{/order}">` | 폼 전송, `name="text"` |
| C-② | `controller/ChatPageController.java` · `order()` | `@PostMapping`, `@RequestParam`, `RedirectAttributes` |
| C-③ | `service/ChatService.java` · `order()`, `repository/BookOrderRepository.java` | 두 표에 저장 |
| C-④ | `ChatPageController.order()`의 `return "redirect:/chat"` | 302, Location, 새로고침해도 다시 보내지 않는 이유 |

### 직접 해 보기
- Network 탭에서 **Preserve log**를 켜고 주문합니다. `order`(302) 다음에 `chat`(200)이 이어집니다.
- 쭌을 퇴근시킨 뒤 주문하면 첫 화면에 빨간 안내가 나오고 적은 글이 입력칸에 남아 있습니다.

### 스스로 답해 보기
- `return "chat"`(redirect 없이)으로 바꾸고 주문한 뒤 새로고침하면 무엇이 일어날까요? (같은 주문이 한 번 더 들어갑니다)

## 흐름 D — 잘못되면 상태코드와 오류 문장이 온다

API에서 생긴 오류는 모두 `api/ApiExceptionHandler`가 같은 모양(`ErrorResponse`)으로 바꿉니다.

```
 요청 ──▶ ChatApiController ── @Valid 실패 ──────────────▶ ① invalid()  → 400 VALIDATION
                     │
                     └▶ ChatService ── FakechatClient 연결 실패 ─▶ ② offline() → 503 LEAD_OFFLINE
                                  └── 없는 번호 ───────────────▶ ③ notFound() → 404 NOT_FOUND
                                                                       │
 chatpanel.js ◀──────────── {"status":…,"code":…,"message":…} ───────┘
 ④ err.textContent = res.body.message
```

| 번호 | 경우 | 실제 응답 |
|---|---|---|
| D-① | 빈 글 `{"text":"  "}` | `400 {"status":400,"code":"VALIDATION","message":"보낼 말을 적어 주세요.",…}` |
| D-② | 쭌이 출근 전 | `503 {"status":503,"code":"LEAD_OFFLINE","message":"쭌이 출근 전이에요. 우분투 창에서 '출근'을 입력한 뒤 다시 보내 주세요.",…}` |
| D-③ | 없는 번호 `GET /api/meeting?bookId=999` | `404 {"status":404,"code":"NOT_FOUND","message":"책을 찾을 수 없어요.",…}` |
| D-④ | 화면 | `chatpanel.js`가 `message`를 빨간 글(`#cp-err`)로 보여 줍니다 |

그 밖의 경우입니다.

## 흐름 E — 사무실 화면이 2초마다 바뀐다

```
 ① GET /office → OfficePageController.office() → office.html (빈 틀 + 대화 패널)
        people.js 가 GET /api/staff 로 직원 명부를 읽는다
 ② office.js poll() ── GET /api/office?after=153 ──▶ ③ OfficeApiController.office(after)
                                                        ▼
                                                    OfficeService.office(after)
                                                      ④ TmuxClient + PaneReading : tmux 칸 화면 → 이름·상태
                                                      ⑤ Repository : 팀원·메시지
                                                      ⑥ 사람마다 상태를 정한다 (작업 중·허용 기다림·대기·자리 비움)
                                                      ⑦ new OfficeResponse(…) → JSON
 ⑧ updateTop · updateDesk · enqueue(봉투) ◀── 200 ──┘
    setTimeout(poll, 2000) → 다시 ②
```

**실제 응답 (줄임)**

```
{"source":"기록","teamName":"session-2d8e941e",
 "book":{"id":2,"title":"20261109-dinosaur","stage":"기획 완료","stageIndex":1,"members":4,…},
 "agents":[{"name":"team-lead","korean":"쭌","role":"편집장","status":"IDLE","statusLabel":"대기",…},
           {"name":"minjun","korean":"민준","status":"OFFLINE","statusLabel":"자리 비움",…}, …],
 "messages":[…,{"id":153,"from":"tepo","fromKorean":"테포","to":"team-lead","category":"보고",…}],

```

- 응답의 `status`가 `office.js`에서 `class="desk s-IDLE"`가 됩니다.
- `office.css`의 `.s-WORKING`, `.s-WAITING` 같은 규칙이 사람 그림을 움직입니다.
- 대화 패널에서 새 메시지가 오면 `chatpanel.js`가 `chat:new` 이벤트를 보내고, `office.js`가 받아 봉투를 날립니다.
- 회의실(`meeting.js` → `GET /api/meeting`)도 같은 방법으로 3초마다 그립니다.

## 흐름 F — 서버가 혼자 기록 파일을 읽어 DB를 채운다

브라우저 요청이 없어도 실행됩니다. 쭌의 답장이 대화방에 나타나는 것은 이 흐름 덕분입니다.

```
 ① ScanScheduler
      @EventListener(ApplicationReadyEvent)  시작 직후 한 번
      @Scheduled(fixedDelay 10초)            그 뒤 10초마다
        ▼
 ② ScanService.scanNow()
        ├─▶ ③ BookScanner.scan()        books/폴더 → book, book_file 표
        └─▶ ④ TranscriptScanner.scan()  *.jsonl 의 새 줄 → chat_message, team_message, team_member, book_session 표
```

**실제 로그와 SQL**

```
INFO … c.g.publisher.scan.ScanScheduler : 관리 화면 준비 완료: 책 5권, 기록 383건 읽음 → http://localhost:8080
update book set chapter_count=?,char_count=?,created_at=?,folder=?,genre=?,stage=?,subtitle=?,title=?,updated_at=? where id=?
insert into team_message (at,from_name,kind,team_name,text,to_name,unique_key,id) values (?,?,?,?,?,?,?,default)
```

같은 기록을 다시 읽어도 두 번 저장하지 않습니다. 그 일은 `existsByUniqueKey`가 맡습니다.

```
select tm1_0.id from team_message tm1_0 where tm1_0.unique_key=? fetch first ? rows only
```

### 직접 해 보기
- 첫 화면의 **지금 다시 읽기**를 누르면 `POST /rescan`이 10초를 기다리지 않고 F-②를 실행합니다.
- 중단점: `TranscriptScanner.handle()`. 쭌에게 말을 보내고 기다리면 쭌의 답장 줄에서 멈춥니다.

### 스스로 답해 보기
