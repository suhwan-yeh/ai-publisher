# 관리 화면 구조 설명 (수업용)

Spring Boot 3 · Spring MVC · Spring Data JPA · Thymeleaf · H2.
화면 데이터를 가져오는 비동기 요청은 **fetch API**로만 보냅니다.

> 요청이 들어와 응답이 나갈 때까지 코드가 실행되는 순서는 [요청 흐름 따라가기](요청-흐름-따라가기.md)에, 낱말 뜻은 [용어 풀이](용어-풀이.md)에, 서버 DB 표는 [DB 표 설명](DB-표-설명.md)에 있습니다.

## 1. 한눈에 보기

```
브라우저
 ├─ 화면 요청 (HTML) ──────▶ controller/  @Controller      → Thymeleaf 템플릿(templates/*.html)
 └─ fetch 요청 (JSON) ─────▶ api/         @RestController  → DTO(record) → JSON
                                   │
                                   ▼
                              service/     @Service   업무 규칙 (검사·조합·트랜잭션)
                               │       │
                               ▼       ▼
                     repository/       client/
                     Spring Data JPA   바깥 세상과 통신
                     (H2 / MySQL)      FakechatClient : 쭌에게 말 전하기 (HTTP)
                               ▲       TmuxClient     : 직원 칸 화면 읽기 (tmux 명령)
                               │
                          scan/  10초마다 책 폴더·대화 기록(jsonl)을 읽어 DB에 저장
```

**규칙 세 가지**
1. Controller는 Service만 부릅니다. Repository나 Client를 직접 부르지 않습니다.
2. API는 엔티티를 그대로 내보내지 않고 **DTO**(`dto/*.java`, record)로 바꿔서 내보냅니다.
3. 오류는 `api/ApiExceptionHandler`가 **상태코드**와 **ErrorResponse** 하나의 모양으로 바꿉니다.

## 2. 패키지별 역할

| 패키지 | 들어 있는 것 | 하는 일 |
|---|---|---|
| `controller` | `DashboardController`, `ChatPageController`, `OfficePageController` | 화면(HTML)을 돌려줌. 폼 전송은 처리한 뒤 다른 주소로 이동(PRG 패턴) |
| `api` | `ChatApiController`, `BookApiController`, `OfficeApiController`, `ApiExceptionHandler` | JSON만 돌려줌. 화면의 fetch가 부름 |
| `dto` | `SendMessageRequest`, `ChatMessageResponse`, `BookSummaryResponse`, `OfficeResponse`, `ErrorResponse` … | 요청·응답 모양. `@NotBlank` 같은 검사 규칙도 여기에 |
| `service` | `ChatService`, `DashboardService`, `OfficeService`, `ScanService`, `PaneReading` | 업무 규칙 |
| `repository` | `BookRepository` 외 6개 | DB 읽고 쓰기 (메서드 이름으로 쿼리 생성) |
| `domain` | `Book`, `ChatMessage`, `TeamMessage`, `BookOrder` … | JPA 엔티티 (DB 표) |
| `client` | `FakechatClient`, `TmuxClient` | 바깥 프로그램과 통신 |
| `config` | `SecurityConfig`, `StaffDirectory`, `PublisherProperties` | 로그인(서버에서만), 직원 명부(staff.yml) 읽기, 경로 설정 |
| `scan` | `BookScanner`, `TranscriptScanner`, `ScanScheduler` | 파일을 읽어 DB를 채움 |

## 3. 주소 목록

### 화면 (@Controller → Thymeleaf)
| 주소 | 템플릿 | 설명 |
|---|---|---|
| `GET /` | index.html | 주문 칸 + 책 목록 + 4가지 점검 |
| `GET /office` | office.html | 사무실 (책상·실제 tmux 화면·봉투 애니메이션·사장실 대화) |
| `GET /meeting` | meeting.html | 회의실 (원탁·말풍선·회의록·다시 보기) |
| `GET /chat` | chat.html | 쭌과 대화 |
| `GET /books/{id}` | book.html | 책 상세 |
| `GET /team` | team.html | 직원 현황 |
| `POST /order` | → `redirect:/chat` | 첫 화면 주문 폼 (실패하면 `redirect:/` + 안내) |
| `POST /rescan` | → `redirect:/` | 지금 다시 읽기 |
| `GET /download/{id}/{kind}` | 파일 | PDF·EPUB·HTML·표지 |
| `GET /chat/{id}/file/{index}` | 파일 | 쭌이 보낸 첨부 |

### REST API (@RestController → JSON)
| 요청 | 성공 | 실패 |
|---|---|---|
| `GET /api/chat?after={id}` | 200 `ChatPollResponse` | 400 숫자가 아님 |
| `GET /api/chat/{id}` | 200 `ChatMessageResponse` | 404 |
| `POST /api/chat` | **201 Created** + `Location` + `ChatMessageResponse` | **400** 빈 글·4000자 초과, **503** 쭌이 출근 전 |
| `GET /api/books` | 200 `BookSummaryResponse[]` | — |
| `GET /api/books/{id}` | 200 | **404** |
| `GET /api/office?after={id}` | 200 `OfficeResponse` | — |
| `GET /api/office/status` | 200 `OfficeStatusResponse` | — |
| `GET /api/staff` | 200 `StaffResponse[]` (직원 명부) | — |
| `GET /api/office/screen/{name}` | 200 `ScreenResponse` | **404** 그 사람 칸이 없음 |
| `GET /api/meeting?after={id}` · `?bookId={id}` | 200 `MeetingResponse` | **404** 없는 책 |

오류 몸통 예:
```json
{ "status": 503, "code": "LEAD_OFFLINE", "message": "쭌이 출근 전이에요. 우분투 창에서 '출근'을 입력한 뒤 다시 보내 주세요.", "timestamp": "2026-11-09T11:02:03Z" }
```

## 4. 요청 하나가 흐르는 길 — "사장님이 주문을 보냄"

1. 사무실 화면의 사장실 패널(`static/js/chatpanel.js`)이 fetch로 `POST /api/chat`을 보냅니다. 몸통은 `{"text":"…"}`입니다.
2. `ChatApiController.send`가 `@Valid SendMessageRequest`를 검사합니다. 빈 글이면 여기서 400으로 끝납니다.
3. `ChatService.send`가 일을 이어받습니다.
   - `FakechatClient.send`가 쭌의 fakechat 서버(`127.0.0.1:8787/upload`)로 말을 전합니다. 실패하면 `ChannelUnavailableException`이 나서 503이 됩니다.
   - 성공하면 `ChatMessageRepository.save`로 DB에 저장합니다.
4. 응답은 201 Created, `Location: /api/chat/{id}`, 몸통 `ChatMessageResponse`입니다. 화면은 말풍선을 붙이고, 사무실은 봉투를 사장실에서 편집장실로 날립니다.
5. 쭌(Claude Code)이 답장(reply 도구)을 보내면 그 내용이 대화 기록(jsonl)에 남습니다.
6. `TranscriptScanner`가 기록을 읽어 `ChatMessage`로 저장합니다. 대화방을 보는 동안은 2초마다 읽습니다.
7. 화면이 3초마다 `GET /api/chat?after=마지막id`를 부르면 새 답장이 옵니다. [제안]이면 ✅ 승인 / ✏️ 수정 / ❌ 거부 버튼이 나타납니다.

## 5. 사무실 화면이 움직이는 원리

- `TmuxClient`는 tmux 명령 두 개(`list-panes`, `capture-pane`)만 **고정된 인자로** 실행합니다. 사용자 입력은 명령에 넣지 않습니다.
- `PaneReading`이 칸 화면의 글자를 해석합니다. 이 부분은 순수 함수라 단위 테스트를 합니다.
  - 칸 제목 → 누구의 칸인지
  - `esc to interrupt` → 작업 중
  - `Do you want to…` → 허용 기다림
  - 마지막 `●` 줄 → 하는 일
  - 쭌 칸의 팀 목록 → 직원별로 맡은 일
- `OfficeService`가 tmux 화면과 DB 기록(누가 누구에게 말했나)을 합쳐 `OfficeResponse`를 만듭니다.
- `office.js`는 2초마다 이 응답을 받아 그립니다.
  - 상태 → 사람 동작: 타이핑, 기대어 쉬기, 손 들기, 빈자리
  - 새 직원 메시지 → 봉투 애니메이션
- tmux가 없으면(예: Windows의 IntelliJ에서 실행) 대화 기록만으로 상태를 짐작하고, 화면에 "대화 기록으로 보는 중"이라고 표시합니다.

## 7. 내 PC 와 서버의 차이

| | 내 PC (기본) | 서버 (`--spring.profiles.active=prod`) |
|---|---|---|
| DB | H2 파일, JPA 가 표 만듦 | MySQL 8, **Flyway** 가 `db/migration` 으로 표 만들고 JPA 는 validate |
| 로그인 | 없음 | Spring Security 폼 로그인 + CSRF |
| 주소 | `localhost:8080` | `127.0.0.1:8080` ← Caddy HTTPS |
| 배포 | `출근` 하면 실행 | GitHub Actions → 서버 교체 (자세히: [배포-설명.md](배포-설명.md)) |
